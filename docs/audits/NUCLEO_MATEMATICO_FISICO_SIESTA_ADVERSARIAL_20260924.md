# Adversarial Audit of the Mathematical Core and Its Coupling to SIESTA

Date: 2026-09-24. Scope: current code, local SIESTA 5.4.2 source, and archived MnO outputs. SIESTA was not run and campaigns were not altered. Synthetic checks were run only in memory. This audit distinguishes (a) demonstrated defects in reusable software, (b) physical-identification limits of the MnO experiment, and (c) assumptions awaiting validation; it does not infer a cause from U merely appearing high.

## Model we actually ran

In MnO, each FDF contains 16 Mn species with the same radial 3d projector, but only one receives nonzero `alpha` (`campaigns/mno_afmii_strict_lr_v3r2/scripts/lru_core.py`, `render_fdf`). `DFTU.PotentialShift true` converts the U field in `DFTU.Proj` into a local shift. SIESTA source (`third_party/siesta-5.4.2-source-audit/Src/dftu.F`, lines 682–689) doubles `Ueff` internally and then applies `0.5*Ueff`; with J=0, the applied operator is `alpha*P`, not `2*alpha*P`. The same overlap matrix `Ski*Sjk` enters the potential and occupation (`dftu.F`, lines 468–470 and 682–689). The printed total occupation sums the traces for both spins (`dftu.F`, lines 519–545). There is no factor of two here and no difference between the stimulus and measurement projectors.

With Hamiltonian mixing, SIESTA computes the first perturbed DM before `setup_hamiltonian(1)` (`siesta_forces.F90`, lines 298–305 and 376–383). In that setup, `hubbard_term` prints the occupation **before** `dhscf`, which rebuilds Hartree–XC (`setup_hamiltonian.F`, lines 284–355). Profile `src/siestaflow_hubbard/siesta_backend/siesta542_bare_profile.py` selects the only block between `stepf` and `scf: 1`, consistent with that sequence. The 14 MnO BARE outputs show that block, and the 14 SCREENED outputs have a final block after convergence (`docs/audits/SIESTA_OUTPUT_TRACE_RECONSTRUCTION_MNO_20260921.md`). This conclusion is limited to the audited 5.4.2 binary/profile and those FDFs.

For each site J and alpha, the total trace `n_I=n_I↑+n_I↓` is fit; measured A/B columns are translated to complete a 16×16 matrix, symmetrized, and used to calculate `K=χ₀⁻¹−χ⁻¹`, `U=mean(diag(K))` (`tools/run_mno_afmii_response_quantized_v1.py`, lines 250–380; `src/siestaflow_hubbard/domain/quantized_response.py`, lines 63–111). The algebraic identity and observed-row/perturbed-column orientation are correct for **that** scalar susceptibility.

Independent reconstruction from the 28 `.out` files, rereading the six-decimal total without reusing the analysis JSON: `U_raw=11.532055662576 eV`, `U_symmetrized=11.532055666425 eV`; for the latter, `U_A=11.530938613583 eV`, `U_B=11.533172719267 eV`. Condition numbers are `2.00484348` and `1.25365363`. They match the previous delivery; no hidden algebra error was detected for this MnO case.

## Prioritized findings

### P0 — Scalar U does not identify the Dudarev coefficient per spin

**Fact.** The stimulus `alpha` acts identically on ↑ and ↓; saved response separates n↑ and n↓, but no run perturbed the spins independently. If `X` is the full 2N×2N susceptibility and `S` duplicates the N scalar fields across both spins, the computed matrix is `χ_c=Sᵀ X S`. In general, `(Sᵀ X S)⁻¹` does not determine the intra-spin part of `X⁻¹`. The measured spin-resolved derivative is `∂n_{Iσ}/∂alpha_J = Σσ′ ∂n_{Iσ}/∂alpha_{Jσ′}`: we know sums of columns, not their components. The 11.5320557 eV result is identified as `U_scalar_charge`; no derivation converts it into `Ueff_Dudarev` for AFM MnO.

**Impact.** Exploratory physical FDFs entered 11.53 eV in `DFTU.Proj` with `PotentialShift false`; that branch uses `Ueff=U−J` and one occupation matrix per spin (`dftu.F`, lines 682–713). [Linscott et al., PRB 98, 235157 (2018)](https://harvest.aps.org/v2/journals/articles/10.1103/PhysRevB.98.235157/fulltext) demonstrate the difference between conventional charge-response U and the intra-spin correction parameter. The distinction is already described in `docs/audits/MNO_SCALAR_SPIN_FUNCTIONAL_MISMATCH_20260923.md`, and guard `src/siestaflow_hubbard/domain/hubbard_parameter_semantics.py` blocks automatic promotion. This is a **proven physical-identification limit**, not proof that scalar 11.53 is arithmetically wrong. The observable test with that value was exploratory and does not validate the functional parameter.

### P1 — Generic fit can fabricate a derivative without changing alpha

`src/siestaflow_hubbard/domain/matrix_lr.py`, `fit_response_matrix`, requires two observations per column but not two **distinct** alpha values. `src/siestaflow_hubbard/domain/scalar_lr.py`, `fit_response`, passes a rank-one design matrix to `np.linalg.lstsq`, which returns a minimum-norm slope instead of rejecting the undefined derivative. Independent synthetic in-memory check: with `alpha=[0.05,0.05]`, BARE occupations `[4,4]`, and SCREENED `[3,3]`, the engine reported `FULL_RANK`, `χ₀=0.19950125`, `χ=0.14962594`, and `U=-1.67083333 eV`. These data contain no response information. `r²` is NaN and also does not prevent inversion. **This is a reproducible defect in the generic core**; it did not affect MnO's seven distinct alpha values.

Correction rule: validate rank two of `[1,alpha]` per column before fitting; reject incompatible duplicates and do not use the rank of matrix `χ` as a substitute for regression identifiability.

### P1 — Generic builder can perturb multiple subspaces

In `src/siestaflow_hubbard/siesta_backend/fdf_builder.py`, `construct_dftu_proj_block` uses `proj_dict.get('alpha', proj_dict.get('U', alpha))`. If multiple projections are supplied without explicit alpha, **all** receive the global alpha. In-memory check: `[{'species':'Fe','n':3,'l':2},{'species':'O','n':2,'l':1}]` and `alpha=0.05` produced `0.0500` for both Fe **and** O. The column is no longer `∂n_I/∂alpha_J` for a single site and cannot be inserted directly into the matrix defined by Cococcioni. Generic BARE is currently disabled, so this example does not explain corrected MnO; it remains a real risk in the reusable SCREENED path and any adaptation that re-enables BARE. Require one explicit target and zero alpha for every other entry.

### P1 — Archived generators still allow a different BARE semantics

The 5.4.2 profile requires diagonalization under Hamiltonian mixing and selects the block between `stepf` and `scf: 1`. However, `tools/build_k_birnessite_initial_lru.py` (lines 83–105), `tools/build_cu3n_projector_campaigns.py` (lines 68–101), and the FeO package described by `tools/build_feo_validation_package.py` (lines 129–144) materialize BARE with `SCF.Mix density`, `MaxSCFIterations 2`, and select a second print by ordinal. The source audit `docs/audits/SIESTA_542_BARE_SOURCE_AUDIT_20260909.md` says this selection is **not certified as frozen χ₀**. I do not conclude that all their results are false; rather, the repository retains paths with incompatible physical contracts that can produce U under a uniform label. They must be blocked for new results or classified as historical semantics until the correct native event is demonstrated.

### P1 — The ±0.060 eV interval covers print rounding only

`fit_centered_linear_response` correctly propagates decimal intervals via `Σ|c_i|h_i`; `inverse_rounding_bound` uses a sufficient spectral invertibility bound (`src/siestaflow_hubbard/domain/quantized_response.py`). The corrected output `analysis-result-corrected-v1.json` reports 11.5320557 eV and `[11.4720889,11.5920224]` eV for the window intersection, **conditional on occupations being exact within the printed decimal half-step**. It excludes SCF truncation, mesh/k error, basis, size, projector, and the P0 functional difference. SCREENED FDFs use `SCF.DM.Tolerance 1e-5` and `SCF.H.Tolerance 1e-4 eV`; there is no propagation from those criteria to χ and U. Also, rereading outputs at alpha zero shows the equivalent A/B runs agree, but BARE occupation after the first diagonalization differs from final reference by up to `7e-6 e` (14 times the printed half-step `5e-7 e`). **This stage difference is not an estimate of noise between replicas**; it only shows restart/convergence control cannot be reduced to format precision. `REPORTABLE_NUMERICAL_U_INTERVAL` is too broad a label if interpreted as total uncertainty.

### P1 — Fourteen MnO columns are inferred by symmetry, not measured

`campaigns/mno_afmii_strict_lr_v3r2/scripts/lru_core.py`, `reconstruct`, generates 16 columns by translating only A and B. This is mathematically valid **if** the 2×2×2 translations exactly preserve AFM structure, bases, pseudopotentials, projectors, and SCF response within the relevant tolerance. The 16 generated radial projectors share a hash and the reference state respects A/B; this supports the hypothesis. However, no perturbation on a translated site directly checks a predicted column. `src/siestaflow_hubbard/domain/symmetry_reduction.py` has a validation plan with shadow columns, but the specific MnO analyzer calls `core.reconstruct` directly without shadow authorization. Thus, symmetrization and the condition number examine only the **reconstructed** matrix and cannot detect symmetry breaking in missing columns. This alone does not explain high U: inverting only the diagonals raises 11.532 to 11.654 eV (`docs/audits/MNO_MATH_CODE_AUDIT_20260923.md`). It does limit certification of the 16×16 value.

### P2 — Fixed internal window and circular fallback in reusable core

`src/siestaflow_hubbard/domain/matrix_lr.py`, lines 208–219, uses `|alpha|<=0.011 eV`; if fewer than two points fit, it defines the internal fit as identical to the full fit. On the MnO mesh, whose smallest nonzero alpha is 0.025 eV, the comparison can report exact equality even if the response is curved. The algebraic check in `docs/audits/MNO_MATH_CODE_AUDIT_20260923.md` demonstrates this defect. The MnO-specific analyzer used three actual windows 0.025/0.05/0.1 eV, so it **did not produce** 11.532 there. The reusable path should choose windows from the actually predeclared alpha values and fail closed if no identifiable internal window exists.

## Negative controls: hypotheses ruled out by current evidence

- No inverted sign or observed/perturbed index confusion in MnO: the stimulated site's slope is negative and the formula is `χ₀⁻¹−χ⁻¹`.
- No hidden factor of two in the SIESTA 5.4.2 shift and no difference between stimulus and occupation projectors within the same run.
- MnO 16×16 inversion is not nearly singular numerically: condition numbers approximately 2.005 and 1.254. Symmetrization changes U by only `3.85e-9 eV`; old rounding changed it by approximately `8.7e-4 eV`. These effects do not explain several eV (`docs/audits/MNO_MATH_CODE_AUDIT_20260923.md`).
- MnO spin-resolved slopes have the same sign; high U is not an artificial cancellation between ↑ and ↓ (`docs/audits/MNO_SCALAR_SPIN_FUNCTIONAL_MISMATCH_20260923.md`).

## Assessment and technical order

The MnO calculation produces an **internally reproducible scalar charge U**, not a Dudarev U or certified physical prediction. The most important scientific defect is spin contraction; the clearest reusable mathematical engine defect is accepting data without alpha rank. Multi-species builders and historical BARE paths are generalization risks that can produce plausible values under semantics different from those declared. The published interval must be explicitly named a rounding bound.

Repair order without choosing a target value: (1) keep promotion `U_scalar_charge→Ueff_Dudarev` blocked and document which spin-resolved response or functional derivation is required; (2) fix alpha identifiability and perturbed-site uniqueness; (3) prevent admission of historical BARE profiles as χ₀; (4) validate or do not use symmetry reduction without shadow columns; (5) separate format bounds from SCF uncertainty and physical convergence. None of these actions requires modifying SIESTA or immediately repeating the full campaign.

## Software remediation applied (2026-09-24)

Source code and campaign generators were changed to: reject fits with repeated alpha or fewer than two distinct values; choose the local window from the measured mesh and fail if none is identifiable; require a single perturbed projector in multi-species blocks; select BARE using `stepf`/`scf: 1` markers, Hamiltonian mixing, and the complete iteration-1 block; and implement this contract in reusable generators for MnO, FeO, β-MnO₂, Cu₃N, and birnessite. Legacy path `observation_selector.py`, which still accepted `scf_iteration == 2` with density/Linear mixing, was disabled for BARE extraction and promotion; the production path uses the output profile tied to binary admission. SIESTA 5.4.2 behavior that forces `DFTU.FirstIteration=true` with `PotentialShift=true` is explicit in the FDFs; the SIESTA engine was not patched because the audited source defines it as intentional behavior, not a defect. The generic analyzer now explicitly labels translation-based column reconstruction as unvalidated. The MnO report distinguishes the rounding interval from total physical uncertainty.

No campaigns or archived results were changed, SIESTA was not launched, and the test suite was not run. Only syntax of the 14 edited Python modules was checked; therefore, remediation is implemented but still requires an explicit request for automated validation before the changes can be declared verified.
